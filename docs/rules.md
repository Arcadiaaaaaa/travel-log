# 字段与规则（单一事实来源）

本文是旅行记录所有客户端（Web、Android、iOS）和服务器必须共同遵守的业务规则。代码与本文不一致时，以本文为准并修正代码；需要修改规则时，先改本文并经过确认，再改代码。

- 接口格式见 [`api/openapi.yaml`](api/openapi.yaml)，架构决策见 [`architecture.md`](architecture.md)。
- 本文描述的是截至 2026-10-18 的现有行为，其中标注 **〔计划〕** 的条目尚未实现。

---

## 2. 行程字段

时间一律是**本地墙上时间**，不带时区，格式 `YYYY-MM-DDTHH:MM`。所有文本在校验前先去掉首尾空白。长度按字符（Unicode 码点）计算。

| 字段 | 类型 | 必填 | 规则 | 适用 |
|---|---|---|---|---|
| `id` | 整数 | — | 服务器生成 | 全部 |
| `transport` | 枚举 | 是 | 见第 1 节 | 全部 |
| `depart_at` | 字符串 | 是 | `YYYY-MM-DDTHH:MM`，必须是真实存在的日期时间 | 全部 |
| `arrive_at` | 字符串 | 是 | 同上，且不早于 `depart_at`（可以相等，可以跨天） | 全部 |
| `price`（输入） | 字符串或数字 | 是 | 单位元，≥ 0，最多两位小数，≤ 1,000,000 元 | 全部 |
| `price_cents`（输出） | 整数 | — | 票价，单位分。导入时也可以直接给 `price_cents`（0 ~ 100,000,000 的整数） | 全部 |
| `distance_km` | 数字 | 否 | 里程，单位公里，≥ 0，最多一位小数，≤ 100,000。留空、`null`、空字符串都记为 `0` | 全部 |
| `seat` | 字符串 | 否 | 必须是该交通方式的坐席选项之一，或空字符串。公交、地铁无论传什么都存为空 | 铁路 |
| `from_place` | 字符串 | 否 | ≤ 50 字。地铁由换乘区段推导，忽略输入（见第 4 节） | 全部 |
| `to_place` | 字符串 | 否 | 同上 | 全部 |
| `train_no` | 字符串 | 否 | ≤ 20 字，转大写。火车是车次号，公交是线路（如「18路」）。地铁一律存为空 | 铁路、公交 |
| `vehicle_model` | 字符串 | 否 | ≤ 50 字，原样保存。地铁一律存为空（车型在区段里） | 铁路、公交 |
| `network` | 字符串 | 否* | 地铁系统，如「北京地铁」，≤ 30 字。非地铁一律存为空。*服务器为兼容旧数据允许为空，客户端保存地铁行程时必须填写 | 地铁 |
| `legs` | 数组 | 是* | 地铁的换乘区段，1 ~ 10 段，见第 4 节。非地铁必须为空数组或不传，否则报错。*地铁行程未传或传空数组时按旧格式兼容处理 | 地铁 |
| `note` | 字符串 | 否 | ≤ 1000 字 | 全部 |
| `created_at` / `updated_at` | 字符串 | — | 服务器本地时间，`YYYY-MM-DDTHH:MM:SS` | 全部 |

### 2.1 客户端输入格式

客户端的表单只接受下面的写法，比服务器宽松的写法（如 `1e2`）一律不在界面上使用：

- 票价：`^\d+(\.\d{1,2})?$`，允许输入前带 `¥`，提交前去掉。
- 里程：`^\d+(\.\d)?$`，可以留空。
- 时间：取输入框值的前 16 个字符（有的系统会带上秒）。

### 2.2 客户端保存前的校验顺序与提示

按顺序检查，遇到第一个问题就停下并显示对应提示：

1. 没选交通方式 →「请选择交通方式」
2. 地铁且没有地铁系统 →「请选择或新增地铁系统，如“北京地铁”」
3. 地铁且第 N 段没有线路 →「第 N 段请选择线路」
4. 没有出发时间 →「请填写出发时间」
5. 没有到达时间 →「请填写到达时间」
6. 到达早于出发 →「到达时间不能早于出发时间」
7. 没有票价 →「请填写票价」
8. 票价格式不对 →「票价请填写数字，最多两位小数」
9. 里程格式不对 →「里程请填写数字，最多一位小数」

服务器还会再校验一次，服务器返回的 `error` 文本直接显示给用户。

## 3. 地铁车型写法

- 预置选项（按此顺序）：`3B、4B、6B、8B、4A、6A、8A、6As、8As、4L、6L`。数字是编组节数，字母是车辆类型。
- 规范化：整串匹配 `(\d+)([A-Za-z])([A-Za-z]*)` 时，写成「数字 + 第一个字母大写 + 其余字母小写」，例如 `6b → 6B`、`6AS → 6As`。不匹配的写法（如「A型车」）原样保存。
- 服务器保存时规范化；客户端下拉里出现的「用过的车型」来自服务器返回的值。

## 4. 地铁换乘区段

一条地铁行程 = 一次进站到出站，可以包含多段（换乘）。票价、时间、里程按整次出行填写。

| 区段字段 | 规则 |
|---|---|
| `line` | 线路，≤ 20 字。服务器允许为空（兼容旧数据），客户端保存时必须填写 |
| `vehicle_model` | 车型，≤ 20 字，按第 3 节规范化 |
| `from_station` | 上车站，≤ 50 字，可以为空 |
| `to_station` | 下车站，≤ 50 字，可以为空 |

- **起点、终点**：`from_place` = 第 1 段的上车站，`to_place` = 最后一段的下车站，由服务器推导。
- **换乘站**：第 i 段（i ≥ 2）的上车站；如果为空，取第 i−1 段的下车站。
- **换乘次数** = 段数 − 1。
- **换乘站不是目的地**：不计入「到过的地点」，不计入常去站点、常去地点、路线排行，只计入「换乘站」排行。
- **旧格式兼容**：地铁行程没有 `legs` 或 `legs` 为空时，服务器用 `train_no`、`vehicle_model`、`from_place`、`to_place` 组成一段（`train_no` 作为线路）。旧版本数据库升级时也这样迁移。

## 5. 表单交互规则

所有客户端的表单行为必须一致。

### 5.1 通用

- **新建时的默认值**：交通方式 = 上次保存成功时用的（没有就用高速动车组）；出发、到达时间 = 当前时间，分钟向下取整到 5 的倍数。
- **出发时间改动后**，如果到达时间为空或早于出发时间，到达时间自动改成和出发时间相同。
- **车次首字母推断**：只在当前选中的是火车类型时生效，输入车次的过程中根据首字母切换：`G` → 高速动车组，`D` → 动车组，`K T Z Y L` 或数字 → 普快火车；`C` 和其他字母不切换。
- **按交通方式显示的字段**：
  - 铁路：出发地、到达地、车次号、型号、坐席。
  - 公交：出发地、到达地、线路（存在 `train_no`）、型号，不显示坐席。
  - 地铁：地铁系统和换乘区段，不显示出发地、到达地、车次号、型号、坐席。
  - 所有交通方式都有：出发时间、到达时间、票价、里程、备注。
- **提示文字**：车次号输入框的标签，铁路叫「车次号」，公交叫「线路」。占位示例：普快 K1234 / 25G，动车 D301 / CRH2A，高铁 G1 / CR400AF，公交 18路 / 宇通 E12。

### 5.2 坐席

- 以单选标签显示该交通方式的坐席选项。可以不选；再点一次已选中的标签就取消选择。
- 切换交通方式时，如果新的选项里还有原来选的坐席（动车组 ↔ 高速动车组），就保留，否则清空。

### 5.3 地铁

- **地铁系统**：下拉菜单，选项是用过的地铁系统（按使用次数从多到少），最后一项是「+ 新增地铁系统…」，选中后出现输入框。新建时默认选中上次保存成功时用的，其次是用得最多的。
- **线路**：下拉菜单，选项是**当前地铁系统**里用过的线路（按段数从多到少），最后一项「+ 新增线路…」。切换地铁系统后，线路选项跟着刷新。
- **车型**：下拉菜单，第一项「不填」，然后是预置车型和用过的其他车型，最后一项「+ 其他车型…」。
- **线路带出车型**：选中线路后，如果这个地铁系统的这条线路以前填过车型，自动填入最近一次的车型（用户可以再改）。
- **车站提示**：上车站、下车站输入时，提示当前地铁系统里用过的车站。
- **换乘站联动**：
  - 点「+ 添加换乘」新增一段时，新一段的上车站自动填为上一段的下车站，并处于「跟随」状态。
  - 处于跟随状态的上车站，会随上一段下车站的改动实时更新。
  - 用户手动改过某段的上车站后，这一段不再跟随。
  - 编辑已有行程时，如果第 i 段的上车站和第 i−1 段的下车站相同，这一段处于跟随状态。
  - 删除某一段后，剩下的跟随段按新的前后关系重新同步；第 1 段永远不跟随。
- **区段显示**：第 1 段的标题是「第 1 段」，上车站标签为「上车站」；第 2 段起标题是「第 N 段 · 在X换乘」，X 为换乘站名，与「在」「换乘」之间没有空格，例如「第 2 段 · 在建国门换乘」（不知道换乘站时为「第 N 段 · 换乘」），上车站标签为「换乘站（上车）」。只有一段时不显示「删除」。

## 6. 导入与导出

- **导出**：JSON 文件 `travel-log-YYYYMMDD.json`，内容为 `{"app": "travel-log", "version": 1, "exported_at": "...", "trips": [...]}`，`trips` 中每条与接口返回的行程相同。
- **导入**：接受导出文件，或直接是行程数组。**只追加**，不覆盖、不去重。一次最多 20,000 条。所有记录先全部校验，任意一条不合法则整批不导入，并提示「第 N 条：原因」。
- 导入时忽略 `id`、`created_at`、`updated_at` 等服务器字段，按导入时间重新生成。

## 7. 列表页

- 列表按出发时间倒序，同一时间按 `id` 倒序，按出发月份分组。分组标题显示「N 次 · 花费」。
- 顶部三个数字（行程、花费、乘车时长）只统计当前筛选范围内的行程。
- 筛选：全部 + 五种交通方式（带数量）。选中地铁时，下方多出一行按地铁系统筛选（全部城市 + 各系统，空系统显示为「未分类」）；切换交通方式时，地铁系统筛选重置为全部城市。
- **卡片**：
  - 标题行：徽标、说明文字、票价。说明文字在地铁行程上是「地铁系统 · 线路1 → 线路2」，在其他行程上是「车次 · 型号 · 坐席」中已填写的部分。
  - 第二行：「出发地 → 到达地」，有一边为空时用「—」代替，两边都空就不显示。
  - 第三行：「出发 → 到达 · 时长」，后面按需加上「· 换乘 N 次」「· 里程」。
  - 有备注时最多显示两行。

## 8. 看板统计口径

### 8.1 范围

- **年份**：按出发时间的年份筛选。跨午夜、跨年的行程归入出发那天。默认选中今年（今年没有记录时选「全部」）。
- **页签**：
  - 总览：全部交通方式。
  - 铁路：普快火车、动车组、高速动车组。
  - 地铁：只有地铁。有两个及以上地铁系统时，多一行城市筛选（全部城市 + 各地铁系统）。
  - 公交：只有公交车。
- 下文「行程」都指当前页签、城市、年份范围内的行程。

### 8.2 数字卡片

| 指标 | 口径 | 出现在 |
|---|---|---|
| 出行次数 | 行程条数。一次多段换乘的地铁算 1 次 | 全部页签 |
| 花费 | `price_cents` 之和 | 全部页签 |
| 乘车时长 | 每条行程（到达 − 出发）分钟数之和 | 全部页签 |
| 里程 | `distance_km` 之和，未填写的按 0 计 | 全部页签 |
| 出行天数 | 不同出发日期的个数 | 总览 |
| 到过的地点 | 不同的非空 `from_place`、`to_place` 的个数（按文字相同合并，换乘站不算） | 总览 |
| 平均票价 | 花费 ÷ 出行次数，四舍五入到分 | 铁路、公交 |
| 坐过的车次 | 不同的非空车次号个数 | 铁路 |
| 坐过的线路 | 公交：不同的非空线路个数；地铁：不同的（地铁系统，线路）组合个数 | 公交、地铁 |
| 换乘 | 每条地铁行程的（段数 − 1）之和 | 地铁 |

### 8.3 构成

- 总览按五种交通方式，铁路按三种列车类型；指标可切换次数、花费、时长、里程。
- 显示一条按比例分段的横条，下方是明细表：名称、数值、占比（保留一位小数）。数值为 0 的行变淡但保留。
- **坐席**（铁路页签）：按行程计数，固定顺序为商务座、一等座、二等座、一等卧、二等卧、软卧、硬卧、硬座、无座、未填写，只显示出现过的项，数值为「N 次 · P%」（P 取整）。
- **城市**（地铁页签，选「全部城市」且有两个及以上系统时）：按行程数排行各地铁系统。

### 8.4 出行趋势

- 切换「月 / 年」视图，指标可切换次数、花费、时长、里程。柱子按交通方式堆叠，点柱子显示各交通方式的数值和合计。
- **月视图**：
  - 选了某一年：显示该年 1 ~ 12 月。
  - 选「全部」：显示从最早一条到最晚一条行程之间的每个月（没有记录的月份也占位）。放不下时可以横向滑动，打开时停在最近的月份。
- **年视图**：始终显示当前页签（和城市）范围内的全部年份，不受顶部年份筛选影响。

### 8.5 出发时间

按出发时间的钟点（0 ~ 23 时）和星期（周一到周日）统计次数，按交通方式堆叠。

### 8.6 排行

- 统一规则：按出现次数从多到少排序，次数相同按名称的中文排序；只显示前 8 名。
- **总览**：地点（每条行程的出发地、到达地各计 1 次）、路线（出发地和到达地都填了才计，「A → B」有方向，A → B 和 B → A 分开计）。
- **铁路**：车站（同「地点」）、路线、车次、车型。
- **公交**：站点（同「地点」）、路线、线路、车型。
- **地铁站点**：分「常去站点」和「换乘站」。常去站点只算每条行程的起点和终点。选「全部城市」时是总排行，站名后标注所属地铁系统，不同城市的同名车站分开计；选某个城市时只排该城市。
- **地铁线路、车型**：按段计数（数值单位为「段」），每个地铁系统分别排行。多个系统时按行程数从多到少依次显示，每组带系统名称。

### 8.7 记录之最

| 项目 | 口径 | 显示条件 |
|---|---|---|
| 最久的一程 | 时长最长 | 总是显示 |
| 最远的一程 | 里程最大 | 最大里程 > 0 |
| 最贵的一程 | 票价最高 | 总是显示 |
| 最早出发 | 出发时刻（只看时分）最早 | 总是显示 |
| 最晚出发 | 出发时刻最晚 | 总是显示 |
| 最忙的一天 | 出发日期相同的行程最多的一天 | 当天至少 2 段 |
| 换乘最多 | 地铁行程段数 − 1 最大 | 总览、地铁页签，且 ≥ 1 |

- 并列时取列表中更靠前的一条，即出发时间最近的那条。
- 点击可以打开对应行程的编辑界面（「最忙的一天」除外）。

## 9. 显示格式

| 内容 | 规则 | 例子 |
|---|---|---|
| 金额 | `¥` + 千分位，整元不带小数，否则两位小数 | ¥553.50、¥5、¥1,234 |
| 金额（数字卡片） | ≥ 1,000 元取整，≥ 100,000 元用「万」，保留一位小数 | ¥9,408、¥12.3万 |
| 时长（单条） | < 60 分钟：「N分钟」；< 1 天：「H小时M分」（M 为 0 时省略）；≥ 1 天：「D天H小时」 | 38分钟、6小时40分、1天2小时 |
| 时长（合计） | < 60 分钟：「N分钟」；否则「H小时」，保留一位小数（≥ 100 小时取整） | 97.7小时、206小时 |
| 里程 | 千分位，最多一位小数 + 「公里」 | 1,318公里、3.5公里 |
| 里程（数字卡片） | 取整，单位写在标签里；≥ 100,000 用「万」 | 11,964 |
| 到达时间 | 与出发同一天只写时刻；次日写「次日 HH:MM」；更晚写「+N天 HH:MM」 | 次日 06:10 |
| 日期（卡片） | 「M月D日 HH:MM」 | 10月1日 23:30 |

## 10. 记忆与本地偏好
